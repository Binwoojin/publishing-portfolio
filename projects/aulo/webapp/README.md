# Aulo 웹앱 (데모)

목적별 공간 추천, Focus·Rest·Suite 예약, 음료 주문을 체험하는 React + Vite 웹앱입니다.
실제 결제·로그인은 없고 예약·주문 기록은 브라우저(localStorage)에만 저장됩니다.

앱 출시를 가정한 프로토타입이라 **반응형을 적용하지 않습니다.** 모든 화면은 모바일 폭(390px) 기준이며,
데스크톱 브라우저에서도 가운데에 390px 앱 화면만 표시됩니다. 390px보다 좁은 폰에서는 화면 폭에 맞춰집니다.

## 실행

```bash
cd webapp
npm install
npm run dev      # 개발 서버 http://localhost:5173
npm test         # 정책 단위 테스트 (Vitest)
npm run build    # dist/ 정적 빌드 (어느 경로에 올려도 동작)
npm run build:artifact  # dist-artifact/ 게시용 빌드 (주소창을 쓰지 않는 메모리 라우터)
```

## 배포 (GitHub Pages)

`.github/workflows/deploy-pages.yml`이 main에 `webapp/` 변경이 올라올 때마다 테스트 → 빌드 → 배포합니다.
Actions 탭의 'Deploy webapp to GitHub Pages' → Run workflow로 직접 실행할 수도 있습니다.

- 처음 한 번: 저장소 **Settings → Pages → Build and deployment → Source**를 **GitHub Actions**로 바꿉니다.
- 주소: `https://binwoojin.github.io/aulo-reservation-app/` (해시 라우터라 새로고침·직접 링크도 동작)
- 테스트가 실패하면 배포하지 않습니다.

## 데모 계정

- 아이디 `demo@aulo.kr` · 비밀번호 `aulo1234` (로그인 화면의 '채우기' 버튼으로 입력)
- 데모 로그인은 형식만 확인합니다(이메일 형식 + 8자 이상).
- 로그인 화면에서 시작 상태(예약 없음 · Focus 이용 중 · Suite 이용 중)를 고르면 그 상태의 기록으로 로그인합니다. 이용 중 상태는 운영 시간(08:10~22:00)에만 고를 수 있고, 이용 중 화면과 재주문 쿠폰(내 쿠폰)을 볼 수 있습니다.

## 구조

| 경로 | 내용 |
|---|---|
| `src/config/policy.js` | 확정 정책과 임시값. **정책 변경은 이 파일만 수정** |
| `src/lib/reservation.js` | 시작·이용 시간, 마감 제한, 충돌 방지, 요금 |
| `src/lib/order.js` | 주문 유형별 할인 (50% 쿠폰 최대 2회, Suite 아메리카노·카페라떼 리필 1회) |
| `src/lib/recommend.js` | 목적·시간·환경 응답 기반 공간 추천 |
| `src/lib/status.js` | 홈 최상단 내 상태(이용 중 > 다가오는 예약 > 예약 없음), 남은 시간 표기 |
| `src/lib/again.js` | 한 번에 다시 하기: 최근 카페 주문 다시 담기, 지난 예약 다시 예약(`/reserve/:type?from=예약id`) |
| `src/lib/scenarios.js` | 데모 시나리오(`/demo` 주소로만): 지금 시각·매장 기준으로 홈 상태별 데모 기록을 만든다 |
| `src/components/StorePicker.jsx` | 지금 매장 선택(홈·주문 탭·장바구니). 고른 매장은 이 기기에 저장되고 앱 전체가 쓴다 |
| `src/lib/assistant.js` | 이용 도우미(데모 챗봇): AI 없이 `policy.js` 정책과 내 예약으로 답하는 규칙 기반 응답. 모르는 질문은 지어내지 않고 이용 안내로 넘김 |
| `src/components/AppShell.jsx` | 앱 바, 하단 탭바(주 메뉴), 하단 액션 바 (보조 메뉴는 홈 맨 아래 '안내 · 고객 지원') |
| `src/pages/` | 홈, 공간 추천(질문 3단계), 예약(단계형), 예약 상세, 음료 주문, 내 예약, 주문 내역, 이용 안내, 이용 도우미(홈 오른쪽 아래 고정 버튼, 홈 맨 아래 '안내 · 고객 지원', 예약 상세에서 진입) |

## 임시값

`brand-landing/CLAUDE_HANDOFF.md`의 '미확정' 항목은 `provisional()`로 감싼 임시값으로 동작하고,
화면에 `임시` 표시와 하단 '임시 정책 안내'가 나타납니다.

- 공휴일 날짜 데이터(`HOLIDAYS`): 2026-12 ~ 2027-12, 대체공휴일 포함·노동절 제외. 월력요항으로 최종 확인 필요
- 음료 가격(메뉴 구성은 확정, 3개 카테고리 13종): 아메리카노 3,000·카페라떼 4,000은 한국소비자원 평균 기준, 나머지는 이 기준에 맞춘 추정값(시럽·소스 음료 4,500, 과일 라떼 5,000, 에이드 4,500, 차 4,000원)
- 좌석 가격: 유사 업종 시장 평균으로 임의 설정(Focus 2,000 · Rest 6,500 · Suite 11,000원/시간). 현장 연장 10분 요금은 시간당 ÷ 6을 100원 단위로 버림(Focus 300 · Rest 1,000원), 연장은 폐점 1시간 전(22:00)까지만, 같은 좌석의 다음 예약과 겹치거나 4시간(최대)으로 예약했으면 연장 불가
- 매장: 성수·연남 대형 카페 2곳, 4가지 공간 모두 운영 (성수 Focus 24 · Rest 18 · Suite 16, 연남 Focus 30 · Rest 20 · Suite 12)

## 범위 밖 (1차)

실제 회원가입·인증 서버, 카카오 로그인, 현장 연장 처리, 결제, 마감 알림, 매장 체크인은 구현하지 않았습니다. 로그인은 데모용으로 형식에 맞는 이메일·비밀번호면 통과하고 이메일만 이 기기에 저장합니다. 예약 취소는 전날까지 예약 상세에서 할 수 있고, 주문 내역은 조회만 됩니다.

## 데모에서 보여 줄 수 없는 정책

- 현장 이용 좌석 공유: 실제 서비스에서는 매장이 현장 이용자를 빈 좌석에 등록해 같은 좌석 현황을 쓴다. 데모는 이 기기의 앱 예약만 알기 때문에 현장 이용 좌석이 비어 보인다.
- 노쇼·지각 페널티: 매장 체크인과 로그인이 있어야 도착 여부와 사람을 알 수 있다. 데모에는 계산 로직(`penaltyStatus`)과 안내 문구만 있고 실제로 페널티를 매기지 않는다.
- 지각 연락: 카카오톡 채널 연락 기능은 추후 개발.
- 스탬프·포인트: 결제가 매장에서 이뤄지므로, 데모는 이용 시작 시각이 지난 예약을 결제된 것으로 보고 적립한다. 포인트 사용은 예약 확인 단계에서 선택하고 예약 취소 시 돌려받는다.

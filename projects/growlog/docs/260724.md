## 2. Attendance 기능의 출석 인정 기준 확정

GrowLog에서 어떤 활동을 출석으로 인정할지 기준을 명확히 정리하였다.

출석으로 인정되는 조건은 다음 두 가지 중 하나 이상을 충족하는 경우이다.

```text
해당 날짜에 목표를 1개 이상 등록
또는
해당 날짜에 성장 기록을 1개 이상 작성
```

즉, 반드시 성장 기록을 작성하지 않더라도 목표를 새로 등록한 날짜는 GrowLog에서 활동한 날로 인정하도록 하였다.

이를 통해 목표 설정과 성장 기록 작성 모두 사용자의 성장 활동으로 반영할 수 있게 되었다.

## 3. AttendanceSummary DTO 구성

Attendance 페이지에서 필요한 여러 데이터를 하나의 객체로 전달하기 위해 `AttendanceSummary` DTO를 사용하였다.

DTO에는 다음 정보가 포함되도록 구성하였다.

```java
public class AttendanceSummary {

    private int currentStreak;
    private boolean attendedToday;
    private int bestStreak;
    private int monthlyAttendanceCount;
    private List<Integer> attendedDays;
}
```

각 필드의 역할은 다음과 같다.

| 필드                       | 역할             |
| ------------------------ | -------------- |
| `currentStreak`          | 현재 연속 출석 일수    |
| `attendedToday`          | 오늘 출석 여부       |
| `bestStreak`             | 최고 연속 출석 일수    |
| `monthlyAttendanceCount` | 이번 달 출석 일수     |
| `attendedDays`           | 이번 달 출석한 날짜 목록 |

Attendance 관련 데이터를 여러 개의 Model 값으로 따로 전달하지 않고 하나의 DTO로 묶어 관리하였다.

## 4. AttendanceService 구성

출석 데이터를 계산하기 위해 `GoalRepository`와 `GrowthRecordRepository`를 함께 사용하였다.

```text
GoalRepository
→ 목표 등록 날짜 조회

GrowthRecordRepository
→ 성장 기록 작성 날짜 조회
```

회원의 활동 날짜를 하나의 날짜 목록으로 합친 뒤 중복 날짜를 제거하여 출석일을 계산하도록 구성하였다.

전체 처리 흐름은 다음과 같다.

```text
로그인 회원 번호 확인
→ 목표 등록 날짜 조회
→ 성장 기록 날짜 조회
→ 두 날짜 목록 통합
→ 중복 날짜 제거
→ 날짜순 정렬
→ 현재 연속 기록 계산
→ 최고 연속 기록 계산
→ 이번 달 출석 현황 계산
```

## 5. GrowthRecordService 메서드 의존 문제 수정

AttendanceService 구현 과정에서 존재하지 않는 Service 메서드를 호출하려는 문제가 있었다.

예를 들어 다음과 같이 작성하려 했지만 실제 `GrowthRecordService`에는 해당 메서드가 없었다.

```java
growthRecordService.countRecordsByMember(memberNo);
```

Attendance 계산에 필요한 데이터는 Repository에서 직접 조회할 수 있으므로 기존 Repository 메서드를 활용하였다.

```java
growthRecordRepository.countByMemberMemberNo(memberNo);
```

단순한 개수 조회뿐 아니라 날짜별 출석 계산에는 회원별 성장 기록 날짜를 조회하는 Repository 메서드를 추가하거나 기존 회원별 기록 조회 결과를 활용하였다.

## 6. MyPageController에 Attendance 페이지 연결

Attendance 페이지를 MyPage의 하위 메뉴로 구성하기 위해 `MyPageController`에 요청 매핑을 추가하였다.

```java
@Controller
@RequiredArgsConstructor
@RequestMapping("/mypage")
public class MyPageController {

    private final AttendanceService attendanceService;

    @GetMapping("/attendance")
    public String attendancePage(
            HttpSession session,
            Model model
    ) {
        Member loginMember =
                (Member) session.getAttribute(
                        "loginMember"
                );

        if (loginMember == null) {
            return "redirect:/login";
        }

        AttendanceSummary summary =
                attendanceService.getAttendanceSummary(
                        loginMember.getMemberNo()
                );

        model.addAttribute(
                "attendanceSummary",
                summary
        );

        return "mypage/attendance";
    }
}
```

회원 개인 활동 데이터이므로 페이지 진입 전에 로그인 세션을 확인하도록 하였다.

## 7. Attendance JSP 화면 구성

`mypage/attendance.jsp`에는 사용자의 출석 현황을 한눈에 확인할 수 있도록 다음 영역을 구성하였다.

```text
월별 출석 달력
현재 연속 기록
최고 연속 기록
이번 달 출석 일수
오늘 출석 여부
```

요약 정보는 DTO의 값을 EL 표현식으로 출력하였다.

```jsp
${attendanceSummary.currentStreak}
${attendanceSummary.bestStreak}
${attendanceSummary.monthlyAttendanceCount}
```

오늘 출석 여부에 따라 안내 문구가 달라지도록 구성하였다.

```jsp
<c:choose>
    <c:when test="${attendanceSummary.attendedToday}">
        오늘도 성장 기록을 남겼어요!
    </c:when>

    <c:otherwise>
        오늘의 목표나 성장 기록을 남겨보세요.
    </c:otherwise>
</c:choose>
```

## 8. JavaScript로 월별 출석 달력 구현

Attendance 페이지의 달력은 `attendance.js`에서 동적으로 생성하도록 하였다.

JSP에서 JavaScript로 출석 데이터를 전달하였다.

```jsp
<script>
    window.attendanceData = {
        attendedDays: [
            <c:forEach
                items="${attendanceSummary.attendedDays}"
                var="day"
                varStatus="status"
            >
                ${day}<c:if test="${!status.last}">,</c:if>
            </c:forEach>
        ]
    };
</script>
```

JavaScript에서는 전달받은 날짜 목록을 확인하여 해당 날짜에 출석 표시를 적용하였다.

```javascript
document.addEventListener("DOMContentLoaded", function () {

    const attendanceData =
        window.attendanceData || {};

    const attendedDays =
        attendanceData.attendedDays || [];

    renderCalendar(attendedDays);
});
```

## 9. 달력 요소를 찾지 못하는 문제 수정

Attendance 달력을 렌더링하는 과정에서 JavaScript가 달력 영역을 찾지 못하는 문제가 발생하였다.

오류의 원인은 `calendarElement`를 선언하지 않았거나 함수의 유효 범위 밖에서 참조한 것이었다.

달력 요소를 먼저 조회하도록 수정하였다.

```javascript
document.addEventListener("DOMContentLoaded", function () {

    const calendarElement =
        document.querySelector(
            ".attendance-calendar"
        );

    if (!calendarElement) {
        return;
    }

    renderCalendar(calendarElement);
});
```

DOM이 완전히 생성된 뒤 JavaScript가 실행되도록 `DOMContentLoaded` 안에서 요소를 조회하였다.

## 10. 성장 기록 작성 후 출석이 표시되지 않는 문제 확인

성장 기록을 한 건 작성한 뒤 Attendance 페이지를 확인했지만 달력에 출석 표시가 나타나지 않는 문제가 있었다.

백엔드 계산 결과보다 JSP에서 JavaScript 데이터로 전달하는 부분을 먼저 확인하였다.

출석 날짜 목록을 JavaScript 배열로 만드는 과정에서 구문이나 변수명이 올바르게 전달되지 않으면 백엔드 데이터가 있어도 화면에는 표시되지 않는다.

JSP의 스크립트 구조를 수정하여 날짜 값이 정상적인 JavaScript 배열로 전달되도록 하였다.

```jsp
window.attendanceData = {
    attendedDays: [
        1, 5, 12, 24
    ]
};
```

수정 이후 성장 기록이 존재하는 날짜가 달력에 정상적으로 표시되는 것을 확인하였다.

## 12. MyPage JSP 경로 점검

MyPage 요청 처리 과정에서 Controller가 존재하지 않는 JSP 파일을 반환하는 문제가 있었다.

예를 들어 다음 View를 반환하면,

```java
return "mypage";
```

View Resolver는 다음 파일을 찾게 된다.

```text
/WEB-INF/views/mypage.jsp
```

하지만 실제 화면 파일은 다음과 같이 하위 폴더에 구성되어 있었다.

```text
/WEB-INF/views/mypage/profile.jsp
/WEB-INF/views/mypage/attendance.jsp
```

따라서 Controller의 반환값을 실제 JSP 구조에 맞게 정리하였다.

```java
return "mypage/profile";
```

MyPage 기본 URL도 프로필 페이지로 리다이렉트하는 방향을 검토하였다.

```java
@GetMapping
public String myPage() {
    return "redirect:/mypage/profile";
}
```

## 14. 비밀번호 재확인 처리

입력한 현재 비밀번호와 DB에 저장된 암호화 비밀번호를 비교하기 위해 `PasswordEncoder.matches()`를 사용하였다.

```java
boolean matches =
        passwordEncoder.matches(
                inputPassword,
                loginMember.getPassword()
        );
```

비밀번호가 일치하면 세션에 계정 설정 인증 상태를 저장하는 구조를 검토하였다.

```java
session.setAttribute(
        "settingsVerified",
        true
);
```

계정 설정 페이지에서는 해당 세션 값이 존재하는지 확인한 뒤 접근을 허용하도록 구성하였다.

```text
settingsVerified = true
→ 설정 페이지 접근 허용

인증 정보 없음
→ 비밀번호 확인 페이지로 이동
```

## 16. 닉네임 중복 확인 구조 검토

닉네임 변경 시 현재 사용 중인 자신의 닉네임은 중복으로 처리하지 않아야 한다.

이를 위해 현재 로그인 회원을 제외하고 닉네임 존재 여부를 검사하는 Repository 메서드를 검토하였다.

```java
boolean existsByNicknameAndMemberNoNot(
        String nickname,
        Long memberNo
);
```

API 요청 구조는 다음과 같은 방향으로 구성하였다.

```text
GET /api/member/nickname/check
```

검사할 닉네임과 현재 로그인 회원 번호를 기준으로 중복 여부를 반환하도록 하였다.

## 17. 계정 설정 화면 레이아웃 수정

MyPage의 퀵 메뉴나 설정 메뉴를 링크로 변경하는 과정에서 `<a>` 태그가 중첩되어 `flex` 레이아웃이 깨지는 문제가 발생하였다.

링크 태그 안에 또 다른 링크 태그가 들어가지 않도록 HTML 구조를 정리하였다.

```jsp
<a href="${pageContext.request.contextPath}/mypage/settings"
   class="mypage-menu-item">

    <span class="menu-icon"></span>

    <span class="menu-text">
        계정 설정
    </span>
</a>
```

카드 전체가 하나의 링크가 되도록 만들고, 내부에는 텍스트나 아이콘 같은 일반 요소만 배치하였다.

## 18. 비밀번호 찾기 기능 구현 시작

로그인하지 못한 사용자가 가입 이메일을 이용해 비밀번호를 다시 설정할 수 있도록 비밀번호 찾기 기능을 구현하기 시작하였다.

전체 흐름은 다음과 같이 설계하였다.

```text
가입 이메일 입력
→ 인증번호 발송
→ 인증번호 확인
→ 새 비밀번호 입력
→ 비밀번호 암호화 후 변경
→ 로그인 페이지 이동
```

페이지 진입 URL은 다음과 같이 구성하였다.

```text
/find-password
```

비밀번호 찾기 과정은 하나의 JSP에서 세션 상태에 따라 단계를 나누어 보여주는 구조를 사용하였다.

## 19. PasswordResetController 구성

비밀번호 재설정 요청을 처리하기 위해 별도의 Controller를 구성하였다.

주요 요청은 다음과 같다.

```text
GET  /find-password
POST /find-password/send-code
POST /find-password/verify-code
POST /find-password/reset
```

단계별 역할은 다음과 같다.

| 요청               | 역할            |
| ---------------- | ------------- |
| `/find-password` | 비밀번호 찾기 화면 출력 |
| `/send-code`     | 인증번호 생성 및 발송  |
| `/verify-code`   | 입력 인증번호 검증    |
| `/reset`         | 새 비밀번호 저장     |

## 20. 비밀번호 재설정 세션 정보 구성

비밀번호 찾기 과정에서도 이메일 인증 상태를 안전하게 유지하기 위해 세션을 사용하였다.

```text
PASSWORD_RESET_EMAIL
PASSWORD_RESET_CODE
PASSWORD_RESET_EXPIRES_AT
PASSWORD_RESET_VERIFIED
```

각 값의 역할은 다음과 같다.

```text
PASSWORD_RESET_EMAIL
→ 비밀번호를 변경할 회원 이메일

PASSWORD_RESET_CODE
→ 발급한 인증번호

PASSWORD_RESET_EXPIRES_AT
→ 인증번호 만료 시각

PASSWORD_RESET_VERIFIED
→ 인증 완료 여부
```

새 비밀번호 변경 요청을 처리할 때는 인증 완료 상태를 다시 확인하도록 설계하였다.

## 21. 비밀번호 찾기 UI 단계 구성

비밀번호 찾기 화면은 세션 또는 Model 상태에 따라 세 단계로 나누었다.

### 1단계: 이메일 입력

```text
가입한 이메일 입력
→ 인증번호 받기
```

### 2단계: 인증번호 확인

```text
인증번호 입력
→ 인증번호 확인
```

### 3단계: 새 비밀번호 설정

```text
새 비밀번호
새 비밀번호 확인
→ 비밀번호 변경
```

JSTL의 조건문을 사용하여 현재 단계에 필요한 form만 출력하도록 구성하였다.

```jsp
<c:if test="${not codeSent}">

</c:if>

<c:if test="${codeSent and not verified}">
    <!-- 인증번호 확인 단계 -->
</c:if>

<c:if test="${verified}">
    <!-- 새 비밀번호 설정 단계 -->
</c:if>
```

## 25. 오늘 배운 점

* 출석 기능은 목표와 성장 기록처럼 여러 데이터 소스를 하나의 날짜 기준으로 합쳐 계산해야 한다.
* 출석 날짜를 합칠 때는 같은 날의 중복 활동을 하나의 출석으로 처리해야 한다.
* DTO를 사용하면 Attendance 페이지에 필요한 여러 값을 하나의 객체로 전달할 수 있다.
* 서버에서 계산된 데이터가 정상이어도 JSP에서 JavaScript로 전달하는 구문이 잘못되면 화면에 표시되지 않는다.
* JavaScript는 DOM이 생성된 이후에 요소를 조회해야 하며, 요소가 없을 가능성도 확인해야 한다.
* Controller가 반환하는 View 이름은 실제 JSP 폴더 구조와 일치해야 한다.
* 중요한 개인정보를 변경하기 전에는 비밀번호를 다시 확인하는 단계가 필요하다.
* 현재 사용자의 닉네임을 중복 검사에서 제외하려면 회원 번호를 함께 조건으로 사용해야 한다.
* HTML에서 `<a>` 태그를 중첩하면 올바르지 않은 구조가 되며 레이아웃과 클릭 동작에 문제가 생길 수 있다.
* 비밀번호 찾기 기능은 인증번호 발송뿐 아니라 이메일, 만료 시각, 인증 완료 상태를 함께 검증해야 한다.

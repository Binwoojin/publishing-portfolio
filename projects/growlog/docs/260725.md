# 📅 GrowLog 개발일지 — 2026.07.25

## 1. 오늘의 개발 목표

전날 비밀번호 찾기 기능의 전체 구조와 Controller를 구성한 데 이어, 오늘은 사용자가 가입 이메일을 이용해 실제로 비밀번호를 재설정할 수 있도록 전체 기능을 완성하는 것을 목표로 하였다.

오늘의 주요 작업 흐름은 다음과 같다.

```text
가입 이메일 입력
→ 이메일 존재 여부 확인
→ 인증번호 생성 및 발송
→ 인증번호 입력 화면 전환
→ 인증번호 검증
→ 새 비밀번호 입력 화면 전환
→ 새 비밀번호 암호화 및 저장
→ 변경된 비밀번호로 로그인 테스트
→ 단계별 UI 보완
```

비밀번호 찾기 기능의 백엔드 로직뿐 아니라 각 단계가 사용자에게 자연스럽게 보이도록 JSP와 CSS도 함께 수정하였다.

---

## 2. 비밀번호 찾기 기능 전체 흐름

로그인하지 못하는 사용자가 가입 이메일을 통해 본인 인증을 완료한 뒤 새로운 비밀번호를 설정할 수 있도록 다음과 같은 단계로 구성하였다.

```text
1단계
가입 이메일 입력

2단계
이메일 인증번호 입력

3단계
새 비밀번호 설정

4단계
로그인 페이지 이동
```

하나의 JSP에서 현재 인증 상태에 따라 필요한 form만 출력하도록 구현하였다.

사용자는 별도의 여러 페이지를 이동하지 않고 한 화면에서 순차적으로 비밀번호 재설정을 진행할 수 있다.

---

## 3. PasswordResetController 구성 보완

비밀번호 찾기 기능은 다음 요청을 기준으로 처리하였다.

```text
GET  /find-password
POST /find-password/send-code
POST /find-password/verify-code
POST /find-password/reset
```

각 요청의 역할은 다음과 같다.

| 요청                   | 기능                 |
| -------------------- | ------------------ |
| `GET /find-password` | 비밀번호 찾기 페이지 출력     |
| `POST /send-code`    | 이메일 확인 및 인증번호 발급   |
| `POST /verify-code`  | 사용자가 입력한 인증번호 확인   |
| `POST /reset`        | 새 비밀번호 암호화 및 DB 저장 |

기능별 요청을 분리하여 각 단계의 책임을 명확하게 구성하였다.

---

## 4. 이메일 입력 단계 구현

첫 번째 단계에서는 사용자가 회원가입에 사용한 이메일을 입력하도록 하였다.

```jsp
<form
    action="${pageContext.request.contextPath}/find-password/send-code"
    method="post"
>
    <label for="email">
        가입 이메일
    </label>

    <input
        type="email"
        id="email"
        name="email"
        required
    >

    <button type="submit">
        인증번호 받기
    </button>
</form>
```

입력한 이메일이 DB에 존재하는 회원 이메일인지 먼저 확인한 뒤 인증번호를 발급하도록 하였다.

```text
이메일 입력
→ 회원 조회
→ 존재하지 않으면 오류 메시지
→ 존재하면 인증번호 생성 및 발송
```

---

## 5. 회원 이메일 존재 여부 확인

사용자가 입력한 이메일에 해당하는 회원을 조회하였다.

```java
Member member =
        memberService.findByEmail(email);
```

해당 이메일의 회원이 존재하지 않을 경우 인증번호를 발급하지 않고 안내 메시지를 반환하도록 하였다.

```java
if (member == null) {
    model.addAttribute(
            "errorMessage",
            "가입된 이메일을 찾을 수 없습니다."
    );

    return "find-password";
}
```

이를 통해 등록되지 않은 이메일에 인증번호가 발급되는 것을 방지하였다.

---

## 6. 인증번호 생성

본인 인증에 사용할 6자리 인증번호를 생성하였다.

```java
String verificationCode =
        String.format(
                "%06d",
                new Random().nextInt(1_000_000)
        );
```

`String.format("%06d", ...)`를 사용하여 숫자가 6자리보다 짧은 경우 앞에 `0`이 포함되도록 하였다.

예시는 다음과 같다.

```text
000481
028134
639205
```

인증번호는 일정 시간이 지나면 사용할 수 없도록 만료 시각도 함께 저장하였다.

---

## 7. 인증번호 이메일 발송

생성한 인증번호를 사용자의 이메일로 전송하기 위해 기존 `EmailVerificationService`를 활용하였다.

```java
emailVerificationService.sendVerificationCode(
        email,
        verificationCode
);
```

이메일에는 사용자가 인증번호를 쉽게 확인할 수 있도록 다음 정보를 포함하였다.

```text
GrowLog 비밀번호 재설정 인증번호
인증번호 6자리
인증번호 유효 시간
본인이 요청하지 않은 경우 안내
```

인증번호를 콘솔로만 확인하는 것이 아니라 실제 가입 이메일로 받을 수 있도록 연결하였다.

---

## 8. 발신자 이메일 설정 문제 보완

이메일 인증번호 발송 과정에서 발신자 주소로 사용할 `senderEmail` 값이 Controller 또는 Service에 준비되지 않아 오류가 발생할 수 있는 부분을 점검하였다.

메일의 발신자 정보는 `application.yaml`에 설정된 값을 사용하도록 구성하였다.

```yaml
spring:
  mail:
    username: ${MAIL_USERNAME}
```

Service에서는 설정값을 주입받아 발신자 주소로 사용하였다.

```java
@Value("${spring.mail.username}")
private String senderEmail;
```

메일을 생성할 때는 다음과 같이 발신자 정보를 지정하였다.

```java
message.setFrom(senderEmail);
message.setTo(email);
```

발신 이메일 정보를 코드에 직접 작성하지 않고 환경 설정으로 분리하여 관리하였다.

---

## 9. 비밀번호 재설정 세션 정보 저장

인증번호 발급 후 다음 단계에서도 이메일과 인증번호를 확인할 수 있도록 세션에 관련 정보를 저장하였다.

```java
session.setAttribute(
        "PASSWORD_RESET_EMAIL",
        email
);

session.setAttribute(
        "PASSWORD_RESET_CODE",
        verificationCode
);

session.setAttribute(
        "PASSWORD_RESET_EXPIRES_AT",
        LocalDateTime.now().plusMinutes(5)
);

session.setAttribute(
        "PASSWORD_RESET_VERIFIED",
        false
);
```

각 세션 값은 다음 역할을 담당한다.

| 세션 이름                       | 역할               |
| --------------------------- | ---------------- |
| `PASSWORD_RESET_EMAIL`      | 비밀번호를 변경할 회원 이메일 |
| `PASSWORD_RESET_CODE`       | 서버에서 생성한 인증번호    |
| `PASSWORD_RESET_EXPIRES_AT` | 인증번호 만료 시각       |
| `PASSWORD_RESET_VERIFIED`   | 본인 인증 완료 여부      |

---

## 10. 인증번호 입력 화면으로 전환

인증번호 발송이 완료된 뒤 JSP가 이메일 입력 form을 계속 보여주는 문제가 발생할 수 있어 화면 상태값을 명확하게 전달하였다.

Controller에서 인증번호가 발송되었다는 상태를 Model에 저장하였다.

```java
model.addAttribute("codeSent", true);
```

JSP에서는 `codeSent` 값에 따라 이메일 입력 form과 인증번호 입력 form을 구분하였다.

```jsp
<c:if test="${not codeSent}">
    <!-- 이메일 입력 form -->
</c:if>

<c:if test="${codeSent}">
    <!-- 인증번호 입력 form -->
</c:if>
```

그러나 POST 요청 이후 다시 페이지를 요청하거나 검증에 실패하면 Model 값이 사라질 수 있으므로, 세션에 저장된 이메일이나 코드 존재 여부를 기준으로 화면 상태를 복구하는 방식도 함께 적용하였다.

## 11. 인증번호 입력 및 확인 기능

사용자가 이메일로 전달받은 인증번호를 입력하도록 두 번째 form을 구성하였다.

```jsp
<form
    action="${pageContext.request.contextPath}/find-password/verify-code"
    method="post"
>
    <label for="verificationCode">
        인증번호
    </label>

    <input
        type="text"
        id="verificationCode"
        name="verificationCode"
        maxlength="6"
        inputmode="numeric"
        required
    >

    <button type="submit">
        인증번호 확인
    </button>
</form>
```

인증번호는 6자리까지만 입력할 수 있도록 제한하였다.

---

## 12. 인증번호 검증 로직 구현

서버에 저장된 인증번호와 사용자가 입력한 인증번호를 비교하였다.

```java
String savedCode =
        (String) session.getAttribute(
                "PASSWORD_RESET_CODE"
        );

LocalDateTime expiresAt =
        (LocalDateTime) session.getAttribute(
                "PASSWORD_RESET_EXPIRES_AT"
        );
```

검증 순서는 다음과 같다.

```text
세션에 인증번호가 존재하는가?
→ 인증번호가 만료되지 않았는가?
→ 입력한 인증번호와 일치하는가?
→ 모두 통과하면 인증 완료
```

만료 시간을 먼저 검사하였다.

```java
if (expiresAt == null
        || LocalDateTime.now().isAfter(expiresAt)) {

    model.addAttribute(
            "errorMessage",
            "인증번호가 만료되었습니다."
    );

    return "find-password";
}
```

인증번호가 다를 경우에는 다시 입력할 수 있도록 오류 메시지를 전달하였다.

```java
if (!savedCode.equals(verificationCode)) {
    model.addAttribute(
            "errorMessage",
            "인증번호가 일치하지 않습니다."
    );

    return "find-password";
}
```

---

## 13. 인증 완료 상태 저장

인증번호가 일치하고 만료되지 않은 경우 세션의 인증 상태를 `true`로 변경하였다.

```java
session.setAttribute(
        "PASSWORD_RESET_VERIFIED",
        true
);
```

JSP에도 다음 화면을 보여주기 위한 상태값을 전달하였다.

```java
model.addAttribute("codeSent", true);
model.addAttribute("verified", true);
```

이후 사용자에게 새 비밀번호 입력 form이 표시되도록 하였다.

---

## 14. 인증번호 실패 시 화면 단계 유지

인증번호가 틀렸을 때 이메일 입력 화면으로 돌아가는 것이 아니라 인증번호 입력 화면을 그대로 유지해야 했다.

따라서 오류가 발생한 경우에도 `codeSent` 상태를 다시 Model에 추가하였다.

```java
model.addAttribute("codeSent", true);
model.addAttribute(
        "errorMessage",
        "인증번호가 일치하지 않습니다."
);
```

이를 통해 사용자는 이메일을 다시 입력하거나 인증번호를 재발급받지 않고 잘못 입력한 인증번호만 수정할 수 있게 되었다.

---

## 15. 새 비밀번호 입력 화면 구현

본인 인증이 완료된 경우 새 비밀번호와 비밀번호 확인 값을 입력하도록 세 번째 form을 출력하였다.

```jsp
<form
    action="${pageContext.request.contextPath}/find-password/reset"
    method="post"
>
    <label for="newPassword">
        새 비밀번호
    </label>

    <input
        type="password"
        id="newPassword"
        name="newPassword"
        required
    >

    <label for="confirmPassword">
        새 비밀번호 확인
    </label>

    <input
        type="password"
        id="confirmPassword"
        name="confirmPassword"
        required
    >

    <button type="submit">
        비밀번호 변경
    </button>
</form>
```

두 비밀번호 값이 일치하는지 서버에서 다시 검증하도록 하였다.

---

## 16. 비밀번호 일치 여부 검증

새 비밀번호와 비밀번호 확인 값이 다르면 변경을 실행하지 않고 다시 입력할 수 있도록 처리하였다.

```java
if (!newPassword.equals(confirmPassword)) {

    model.addAttribute("codeSent", true);
    model.addAttribute("verified", true);

    model.addAttribute(
            "errorMessage",
            "새 비밀번호가 서로 일치하지 않습니다."
    );

    return "find-password";
}
```

검증 실패 후에도 인증 완료 상태를 유지하여 사용자가 처음 단계부터 다시 진행하지 않도록 하였다.

---

## 17. 인증 완료 여부 재검증

새 비밀번호를 저장하기 전에 세션에 인증 완료 상태가 있는지 다시 확인하였다.

```java
Boolean verified =
        (Boolean) session.getAttribute(
                "PASSWORD_RESET_VERIFIED"
        );

if (!Boolean.TRUE.equals(verified)) {
    return "redirect:/find-password";
}
```

사용자가 인증 과정을 건너뛰고 `/reset` 요청을 직접 전송하더라도 비밀번호가 변경되지 않도록 보호하였다.

---

## 18. 새 비밀번호 암호화 및 저장

본인 인증과 비밀번호 일치 검증이 완료된 후 DB에 저장할 새 비밀번호를 암호화하였다.

```java
String encodedPassword =
        passwordEncoder.encode(newPassword);
```

이후 세션에 저장한 이메일을 이용해 회원을 조회하고 비밀번호를 변경하였다.

```java
String email =
        (String) session.getAttribute(
                "PASSWORD_RESET_EMAIL"
        );

memberService.updatePassword(
        email,
        encodedPassword
);
```

기존 비밀번호처럼 새 비밀번호도 평문으로 저장하지 않고 `PasswordEncoder`를 통해 암호화하여 저장하였다.

---

## 19. MemberService 비밀번호 변경 처리

비밀번호 변경 로직은 Controller에 직접 작성하지 않고 `MemberService`에서 처리하도록 구성하였다.

```java
@Transactional
public void updatePassword(
        String email,
        String encodedPassword
) {
    Member member =
            memberRepository.findByEmail(email)
                    .orElseThrow(() ->
                            new IllegalArgumentException(
                                    "회원을 찾을 수 없습니다."
                            )
                    );

    member.setPassword(encodedPassword);
}
```

트랜잭션 내부에서 조회한 Entity의 비밀번호를 변경하여 JPA 변경 감지로 DB에 반영되도록 하였다.

---

## 20. 비밀번호 변경 완료 후 세션 초기화

비밀번호 재설정이 완료된 뒤 세션에 인증번호와 인증 상태가 남아 있으면 다시 사용될 위험이 있으므로 관련 값을 제거하였다.

```java
session.removeAttribute(
        "PASSWORD_RESET_EMAIL"
);

session.removeAttribute(
        "PASSWORD_RESET_CODE"
);

session.removeAttribute(
        "PASSWORD_RESET_EXPIRES_AT"
);

session.removeAttribute(
        "PASSWORD_RESET_VERIFIED"
);
```

비밀번호 찾기 과정에서 사용한 임시 인증 정보만 제거하고, 현재 로그인 세션과는 별도로 관리하였다.

---

## 21. 비밀번호 변경 완료 메시지 처리

비밀번호 변경이 완료되면 사용자가 결과를 알 수 있도록 성공 메시지를 전달하였다.

```java
redirectAttributes.addFlashAttribute(
        "successMessage",
        "비밀번호가 변경되었습니다. 새 비밀번호로 로그인해 주세요."
);
```

이후 로그인 페이지로 이동하도록 처리하였다.

```java
return "redirect:/login";
```

Flash Attribute를 사용하면 리다이렉트 이후에도 한 번만 메시지를 전달할 수 있다.

## 22. 변경된 비밀번호 로그인 테스트

확인한 항목은 다음과 같다.

```text
기존 비밀번호로 로그인 실패
```

## 23. 비밀번호 찾기 화면의 서버 메시지 구성

비밀번호 찾기 과정에서 발생하는 오류와 성공 결과를 사용자에게 보여주기 위해 JSP에 메시지 영역을 추가하였다.

```jsp
<c:if test="${not empty errorMessage}">
    <div class="password_find_message error">
        <c:out value="${errorMessage}"/>
    </div>
</c:if>

<c:if test="${not empty successMessage}">
    <div class="password_find_message success">
        <c:out value="${successMessage}"/>
    </div>
</c:if>
```

오류 메시지와 성공 메시지에 서로 다른 CSS 클래스를 적용하여 시각적으로 구분하였다.

## 24. 인증번호 확인 화면 UI 보완

인증번호 입력 단계는 처음 추가했을 때 HTML의 기본 스타일만 적용되어 다른 로그인·회원가입 화면과 디자인이 통일되지 않았다.

인증번호 입력 영역에 별도의 클래스를 적용하고 다음 요소를 정리하였다.

```text
입력 필드 너비
라벨과 입력창 간격
인증번호 확인 버튼
이메일 안내 문구
오류 메시지
이전 단계와의 간격
```

인증번호를 입력해야 하는 이유와 발송된 이메일을 확인하라는 안내 문구도 함께 배치하였다.

## 25. 새 비밀번호 설정 화면 UI 보완

새 비밀번호 입력 필드와 새 비밀번호 확인 필드의 간격이 지나치게 가까워 하나의 입력 영역처럼 보이는 문제가 있었다.

각 입력 항목을 개별 form group으로 묶어 간격을 조정하였다.

```jsp
<div class="password_find_field">
    <label for="newPassword">
        새 비밀번호
    </label>

    <input
        type="password"
        id="newPassword"
        name="newPassword"
    >
</div>

<div class="password_find_field">
    <label for="confirmPassword">
        새 비밀번호 확인
    </label>

    <input
        type="password"
        id="confirmPassword"
        name="confirmPassword"
    >
</div>
```

CSS에서는 form group 사이에 충분한 간격을 적용하였다.

```css
.password_find_field + .password_find_field {
    margin-top: 18px;
}
```

이를 통해 두 입력 항목이 명확하게 구분되도록 수정하였다.

## 26. 비밀번호 입력 안내 UI 구성

사용자가 새로운 비밀번호 조건을 쉽게 이해할 수 있도록 도움말 또는 툴팁 영역을 구성하였다.

```text

```

단순히 입력 오류가 발생한 이후 메시지를 보여주는 것보다 입력 전에 조건을 안내하여 사용자 경험을 개선하였다.

## 30. 오늘 배운 점

* 비밀번호 찾기는 이메일 발송 기능만으로 끝나지 않고 단계별 인증 상태를 안전하게 관리해야 한다.
* POST 요청 후 같은 JSP를 반환하면 Model 상태값을 다시 전달해야 올바른 단계가 유지된다.
* 인증번호가 틀렸을 때 사용자가 이메일 입력부터 다시 하지 않도록 현재 화면 상태를 보존해야 한다.
* 인증번호에는 반드시 만료 시간이 필요하다.
* 새 비밀번호 저장 요청에서는 인증 완료 여부를 다시 확인해야 한다.
* 사용자가 보낸 이메일이나 인증 여부를 클라이언트 값만으로 신뢰해서는 안 된다.
* 비밀번호는 항상 `PasswordEncoder`를 이용하여 암호화한 뒤 저장해야 한다.
* 비밀번호 변경 후 인증번호와 인증 상태는 세션에서 제거해야 한다.
* Redirect 이후 메시지를 전달하려면 Flash Attribute를 사용할 수 있다.
* 백엔드 기능이 정상적으로 작동한 뒤에도 단계별 화면과 입력 필드 간격을 보완해야 완성도 있는 기능이 된다.

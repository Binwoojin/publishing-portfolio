# 전체 80개 화면 배치·이미지 변환 검토

1. 원본 HTML의 공통 카드·칩·그리드·폼 스타일이 누락되어 생기던 간격 차이: 원본 inline CSS 및 최신 공통·타이포그래피 CSS를 wireframe-base.css에 함께 반영.
2. 기존 와이어프레임이 모든 appbody padding을 20px로 강제하던 문제: 강제 규칙 삭제. 원본의 화면별 패딩 유지. 채팅 화면은 원본처럼 외곽 패딩 없이 내부 목록·입력 영역의 패딩을 사용.
3. 카드·입력칸·배너에 별도 테두리와 모서리를 일괄 추가하던 문제: 제거하여 원본의 영역 크기 유지.
4. 와이어프레임이 제목 크기를 일괄 덮어쓰던 문제: 원본의 화면별 위계·굵기·크기를 재사용.
5. 프레임 기준: 전 화면 폭390px·높이844px, 헤더60px·하단 메뉴64px. 인증 화면은 기존처럼 하단 메뉴 제외.
6. 목록·상세의 iframe 표시를 SVG 이미지로 교체. 80개 화면마다 다운로드 가능. 첫 화면 아래로 이어지는 내용은 정적 와이어프레임 HTML에서 확인.

SVG는 실제 와이어프레임 HTML과 같은 스타일을 내장한 벡터 이미지입니다. HTML 기반 벡터 표현(foreignObject)을 사용하므로 웹 브라우저에서 열람하는 용도입니다. 일부 디자인 편집기에서는 해당 이미지의 내부 텍스트·도형 편집을 지원하지 않을 수 있습니다. 페이퍼로지 400·500·600·700 웹폰트를 SVG에 내장해 외부 로딩 없이 동일하게 표시합니다.

검증: 80개 화면 재추출·이미지 XML 유효성·파일 경로·이미지 뷰어 동작 검증. 브라우저 보안 제한으로 실제 화면의 픽셀 간격 측정 및 전체 시각 캡처 검수는 수행하지 못했습니다. 원본 자체의 화면별 간격을 임의로 동일화하지 않고 원본 스타일과 일치시키는 데 중점을 두었습니다.

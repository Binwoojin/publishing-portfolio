# 모바일 와이어프레임 제작 기준

- Figma 모바일 와이어프레임 사례: https://www.figma.com/wireframe-tool/
- NN/g 모바일 Wireflows 사례: https://www.nngroup.com/articles/wireflows/
- Figma 앱 설계 안내: https://www.figma.com/resource-library/how-to-design-an-app/

사례의 회색조, 반복 컴포넌트, 화면 프레임, 화면 옆 설명 방식을 참고했습니다. 외부 UI 키트나 이미지를 복제하지 않았습니다.

현재 스토리보드 80개 화면의 렌더링 결과와 최신 화면 명세를 사용합니다. 제품색·그림자·모션을 제거하고 입력칸·버튼·선택 상태·콘텐츠 영역을 구분했습니다. 모든 화면은 390×844px 기본 프레임, 내용이 긴 화면은 내부 스크롤입니다. 원본 컴포넌트 배치를 유지한 중간 충실도 구조 검토본입니다.

검토 기준: 화면 목적, 콘텐츠 우선순위, 입력 순서, CTA 위치, 선택·빈 상태의 구분, 다음 화면 연결. 폼을 실제 제출하거나 AI 생성·결제를 실행하지 않는 정적 검토본입니다.

기본 회원 화면은 무료 회원 시안 상태를 사용합니다. 회원 상태나 운동 전후 등 모든 경우의 수를 80개 별도 화면으로 오인해 추가하지 않습니다. 동적 상태를 조작하려면 원본 스토리보드를 사용합니다. 화면 명세의 과거 표현이 현재 구현과 다르면 원본 구현을 우선해 검토해야 합니다.

기존 *_wire.png 파일은 오래된 산출물이 섞여 있으므로 재사용하지 않았습니다. 이번 결과는 모바일_와이어프레임 폴더에 별도로 저장했습니다.

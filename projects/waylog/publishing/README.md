# WayLog 리디자인 — 웹 퍼블리싱

> 국내 여행지를 찾고, 코스를 따라 떠나고, 다녀온 이야기를 피드로 나누는 여행 기록 서비스 **WayLog**를
> 새 디자인 시스템으로 리디자인하고, 10개 화면을 HTML · CSS · JavaScript로 퍼블리싱했습니다.

- **원본 프로젝트**: React 19 + Spring Boot 모노레포 ([Binwoojin/waylog](https://github.com/Binwoojin/waylog), 원본 소스는 `../`에 보관)
- **이번 작업**: 원본의 화면 구성 · 검증 규칙 · 상태 처리를 바탕으로 **디자인을 새로 잡고**, 서버 없이 동작하는 **정적 퍼블리싱본**으로 다시 만들었습니다.
- **역할**: 디자인 · 퍼블리싱 100%

## 화면 구성

| 화면 | 파일 | 확인 포인트 |
|---|---|---|
| 홈 | `index.html` | **모션 히어로**(전국을 잇는 경로 · 떨어지는 핀 · 이동하는 여행자 · 좌표 HUD), 지역 레일, 탑승권 코스 카드, 즐길거리 탭, 이번 주 행사 — 섹션마다 스크롤 등장 연출 |
| 여행지 찾기 | `destinations.html` | 지역 칩 · 유형 탭 · 검색어 · 정렬 · 페이지가 **주소(URL)와 동기화**, 결과 없음 화면, 조건 초기화 |
| 여행지 상세 | `place.html?id=p1` | 사진 + 좌표, 저장 · 공유, 이용 안내 카드(고정), 이곳을 태그한 여행 이야기 |
| 코스 상세 | `course.html?id=c1` | 지점별 일정 타임라인, 지점 간 직선거리 계산, **좌표를 같은 축척으로 그린 SVG 경로 지도**(축척 막대 · 라벨 겹침 회피) |
| 여행 즐기기 | `enjoy.html?category=festivals` | 분류 탭, 행사 기간 필터(진행 중 · 예정 · 종료), 분류별 커버 |
| 여행 피드 | `feed.html` | 더 보기, 태그 필터, 글쓰기 다이얼로그(사진 형식 · 용량 · 개수 검사, 위치 · 코스 태그, 해시태그 입력) |
| 게시물 상세 | `post.html?id=f3` | 좋아요 · 저장, 댓글 작성 · 삭제 확인, 내 글 삭제 |
| 마이페이지 | `mypage.html` | 비로그인 안내, 프로필 · 통계, 탭(내가 쓴 글 · 저장한 항목 · 계정 설정) |
| 로그인 | `login.html` | 검증, 실패 알림, 로그인 후 원래 보던 화면으로 복귀(`?next=`) |
| 회원가입 | `signup.html` | 3단계(약관 → 정보 입력 → 완료), 이메일 중복 확인 + 인증번호 타이머, 비밀번호 규칙 실시간 표시, 닉네임 중복 확인 |

**데모 값**: 로그인 `traveler@waylog.kr` / `waylog123!` (로그인 화면의 ‘자동 입력’ 버튼) · 회원가입 인증번호 `246810`.
저장 · 좋아요 · 새 글 · 댓글은 브라우저(localStorage)에만 저장됩니다.

여행지 찾기 · 상세 · 피드 화면 상단의 **화면 상태 미리보기**로 `기본 / 로딩 / 빈 상태 / 오류` 화면을 바로 바꿔 볼 수 있습니다. (`?state=error`처럼 주소로도 가능)

## 디자인 시스템 — "Route Note"

지도 위에 찍은 핀과 점선 경로, 여행 노트를 컨셉으로 잡았습니다. 색상은 **원본 WayLog 의 값을 기준**으로 정리했습니다.

| 토큰 | 값 | 원본 근거 · 용도 |
|---|---|---|
| `--c-primary` | `#2563EB` | 원본 버튼 파랑 `#2878ED` 계열. 원본 값은 흰 글자 대비 4.2:1 이라, 같은 계열에서 5.2:1 이 되는 값으로 맞춤 — 주요 버튼 · 경로선 · 저장 |
| `--c-accent` | `#38A8F8` | 원본 로고 그라데이션(`#2F6CFD → #29A0F8`)의 하늘색 — 핀 · 현재 위치 · 마지막 코스 지점 |
| `--c-ink` | `#17263A` | 원본 상세 화면 제목 남색 — 본문 |
| `--c-bg` · `--c-line` | `#F4F7FB` · `#DBE4EE` | 원본의 청회색 면 · 테두리(`#F3F7FB`, `#DCE7F2`) |
| `--c-footer-bg` | `#14345F` | 원본 푸터 남색 |
| `--c-like` | `#E5484D` | 좋아요 하트 (원본에 없던 상태 색, 파랑 계열과 구분) |
| 로고 | `images/logo-*.webp` | 원본 로고(`frontend/src/assets/figma/logo.png`)를 30 · 60 · 90px(1x · 2x · 3x)로 축소. 어두운 배경용은 같은 그라데이션을 40% 밝힌 `logo-dark-*.webp`(다크 배경 대비 6.6:1, 원본 그대로는 3.2:1) |
| 폰트 | Hahmlet / IBM Plex Sans KR / IBM Plex Mono | 제목 · 본문 · 좌표와 날짜 |

- 좌표(`33.4580°N 126.9425°E`), 행사 날짜, 거리 같은 **데이터 글자는 고정폭 글꼴**로 구분
- 코스 카드는 **탑승권 절취선** 모양, 지도의 경로는 **점선**으로 통일
- 색 · 간격 · 모서리 · 그림자를 모두 CSS 변수로 정의하고, **다크 모드**는 시스템 설정과 `data-theme` 속성 모두 지원
- 로고는 테마에 따라 원본 / 다크 버전으로 바뀌고, 남색 푸터에서는 테마와 관계없이 다크 버전을 사용
- 글자색 조합은 라이트 · 다크 모두 명도 대비 4.5:1 이상

## 퍼블리싱 포인트

**마크업 · 접근성**
- 랜드마크와 제목 단계, 본문 바로가기, 현재 위치(브레드크럼 · `aria-current`)
- 탭은 WAI-ARIA Tabs 패턴(`role="tab"`, 화살표 · Home · End 키 이동, `aria-selected`, `tabindex` 관리)
- 필터 칩 · 좋아요 · 저장 버튼은 `aria-pressed`로 상태 전달
- 폼: 라벨 연결, 오류 문구 `aria-describedby` 연결, 제출 실패 시 오류 요약으로 포커스 이동
- 다이얼로그 · 모바일 메뉴는 네이티브 `<dialog>` — 바깥 비활성화, ESC 닫기, 닫힌 뒤 원래 버튼으로 포커스 복귀
- 로그인이 필요한 동작(저장 · 좋아요 · 글쓰기 · 댓글)은 안내 다이얼로그 → 로그인 → 원래 화면 복귀
- 코스 지도는 `role="img"` + 경로 순서를 담은 설명 제공
- 클릭 영역 44px 이상, 포커스 링, `prefers-reduced-motion` 대응

**레이아웃 · 반응형 · 성능**
- 모바일 우선, 주요 분기 560 · 768 · 900 · 1024 · 1200px
- 320(WCAG 1.4.10 리플로우 기준) · 375 · 390 · 768 · 1024 · 1440px에서 가로 스크롤 없음 확인
- 원본 사진 28장(약 53MB PNG)을 **WebP 400 · 800px(큰 사진은 1600px까지)로 변환(약 3.6MB)**, `srcset` + 실제 표시 폭에 맞춘 `sizes`로 기기에 맞는 크기만 내려받기
- 첫 화면 사진은 바로 불러오고(`fetchpriority`, 첫 게시물 사진은 `eager`), 나머지는 지연 로딩
- 웹폰트 CSS 를 비동기로 불러와 첫 화면 표시를 막지 않게 하고, 실제 쓰는 굵기만 요청
- 본문 최소 높이를 화면 높이로 잡아, JS 가 그리기 전 푸터가 보였다가 밀리는 레이아웃 이동(CLS)을 막음
- 화면 CSS에 인라인 `style` 속성 없음
- 이미지 영역은 `aspect-ratio`로 미리 자리를 잡아 레이아웃 밀림 방지

**홈 모션 — "핀을 찍고, 점선 경로를 따라 떠난다"**
- 히어로: 제목이 한 줄씩 올라오고 `모두의 여행` 아래 점선이 그어짐, 좌표 배지 글자가 뒤섞였다 맞춰짐, 검색 패널 · 테마 칩이 튀어오름, 검색어 예시가 한 글자씩 바뀜(입력 시 정지)
- 사진 위로 제주 → 여수 → 부산 → 강릉 → 서울 경로가 그려지고(SVG 마스크 + `stroke-dashoffset`) 핀이 차례로 떨어짐. 이후 여행자 점이 경로를 계속 돌며 지나는 핀을 튕기고, 오른쪽 HUD 에 지점 이름 · 좌표를 표시(넓은 화면)
- 스크롤: 헤더 아래 경로 진행 막대와 핀, 히어로 사진 시차, 코스 사진 · 기록 배너 시차
- 섹션: 영문 머리글 · 좌표 스크램블, 제목이 아래에서 열림, 지역 사진이 아래에서 현상되듯 열림, 코스 카드가 탑승권처럼 인쇄되듯 내려오고 경유지가 점선으로 이어짐, 탭 표시줄이 미끄러지고 카드가 다시 등장, 행사 날짜가 출발 안내판처럼 넘어감, 기록 배너 뒤 점선 궤도 회전
- 성능: 경로 계산은 경로가 보이는 넓은 화면에서만 첫 화면을 그린 뒤 실행, 스크롤 처리는 읽기 → 쓰기 순서로 묶어 강제 레이아웃 방지, 글자 스크램블은 약 15회/초로 제한(모바일 TBT 250ms → 50ms 대)
- 히어로가 화면 밖이면 반복 모션 정지, `prefers-reduced-motion` 이면 완성된 화면을 바로 표시

**인터랙션 (Vanilla JS, 라이브러리 없음)**
- 사용자 입력과 데이터는 모두 이스케이프 후 출력
- 코스 거리: 하버사인 공식으로 지점 간 직선거리 계산
- 코스 지도: 위도에 따라 경도 간격을 보정한 등장방형 투영으로 그리고, 축척 막대를 같은 축척에서 계산
- 글쓰기 사진은 캔버스로 640px까지 줄여 미리보기

## 검증 결과

| 도구 | 결과 |
|---|---|
| html-validate (권장 규칙) | 오류 0 |
| axe-core (WCAG 2.1 · 2.2 AA + 모범 사례) | 위반 0 — 전 화면 × 데스크톱 · 모바일 × 라이트 · 다크 × 로그인 전후, 다이얼로그 · 오류 · 빈 상태, 홈 모션 재생 중 포함 |
| Lighthouse (모바일 / 데스크톱) | 성능 96~99 / 100, 접근성 100, 권장사항 100, SEO 100, CLS 0.07 이하 |
| 키보드 | 모든 화면 첫 Tab 이 본문 바로가기, 포커스 링 표시, 숨은 요소로 포커스 이동 없음 |
| 링크 | 깨진 링크 · 이미지 0 |

개선 전 모바일 성능은 59~65점(LCP 5.8~8.1초)이었습니다. 이미지를 표시 폭에 맞춰 내려받게 하고 웹폰트를 비동기로 바꿔 96~99점(LCP 1.7~2.6초)으로 올렸습니다.
Chromium 기준 결과이며, Safari · Firefox 와 실제 스크린리더(NVDA · VoiceOver)는 직접 확인이 필요합니다.

## 폴더 구조

```
publishing/
├── index.html · destinations.html · place.html · course.html · enjoy.html
├── feed.html · post.html · mypage.html · login.html · signup.html
├── css/
│   ├── base.css        # 토큰 · 다크 모드 · 기본 스타일
│   ├── components.css  # 버튼 · 폼 · 칩 · 탭 · 카드 · 상태 화면 · 다이얼로그 · 토스트
│   ├── layout.css      # 헤더 · 회원 메뉴 · 모바일 메뉴 · 푸터
│   ├── pages.css       # 코스 카드 · 게시물 카드 · 검색 조건 (여러 화면 공용)
│   └── home.css · detail.css · enjoy.css · feed.css · mypage.css · auth.css
├── js/
│   ├── icons.js · data.js · common.js
│   └── home.js · destinations.js · place.js · course.js · enjoy.js · feed.js · post.js · mypage.js · auth.js
└── images/             # WebP 사진
```
